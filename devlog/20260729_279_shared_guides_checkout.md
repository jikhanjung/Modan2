# 공통 가이드를 복사하지 않고 참조하기로 — 이 저장소가 드리프트의 원인 쪽이었다

## 날짜
2026-07-29

## 한 일

1. `.guides/` — 공유 가이드 체크아웃을 가리키는 심볼릭 링크. `.gitignore` 대상.
2. `CLAUDE.md` 에 진입 지점 절 신설 + "Where the user's files live" 에 교차 참조.
3. 코드 변경 없음.

## 왜 복사가 아니라 참조인가 — 하필 이 프로젝트의 판단이 굳을 뻔했다

공유 가이드 묶음은 원래 첫머리에 *"이 디렉터리를 프로젝트 `docs/` 로 복사해 계약으로
채택하라"* 고 적고 있었다. 이식용 표준이라면 당연한 문장이고, 여기서도 그렇게 할 참이었다.

**그런데 그 실패 모드의 첫 사례가 이 저장소에서 나왔다.**

`guides/desktop/file-locations.md` §5 는 [P03](20260728_P03_data_directory_relocation_plan.md)
**초안** 을 일반화한 것이었고, 초안의 절충안 — **미디어·백업은 `Documents`, DB 는 로컬 고정**
— 을 *"필요하면 이렇게 갈라 두라"* 는 **권고로 실었다.** 그리고 하루도 안 되어 [278](20260729_278_storage_directory_configurable.md)
에서 P03 을 개정하며 **그 절충안을 기각했다.** 근거는 DB 없는 `data/` 는 객체 id 로 이름 붙은
파일 더미이고 랜드마크 좌표는 DB 에만 있으므로 **`Documents` 만 백업되면 복구 가치가 0** 이라는
것이었다.

즉 이 저장소는 드리프트의 피해자가 아니라 **원인 쪽** 이었다. 가이드는 알 수 없었다 —
스냅샷을 일반화한 문서인데 스냅샷이 움직였기 때문이다. 그리고 **사본은 자기가 낡았다고
알려 주지 않는다.**

만약 네 프로젝트가 "복사해서 채택하라" 를 곧이곧대로 따랐다면, **이 프로젝트가 하루 만에
철회한 판단이 형제 저장소 세 곳에 사본으로 남아** 각자의 시계로 낡았을 것이다. 그리고 그것을
정정하려면 네 곳을 찾아다녀야 했을 것이다.

그래서 `.guides/` 는 심볼릭 링크다. 갱신은 체크아웃에서 `git pull` 이고, 소유자가 하나이므로
이 드리프트가 권고 사항이 아니라 **구조적으로 불가능** 해진다. 커밋하지 않는 이유는 별개다 —
가이드는 비공개이고 이 저장소는 공개라, 커밋도 `docs/` 복사도 곧 공개다(검토했다가 접은
발행안과 같은 결과).

## 미해결 — `docs/CODE_QUALITY_GUIDE.md` 와 공유 가이드 중 무엇이 정본인가

다른 세 프로젝트에게 공유 가이드는 순수하게 외부 문서지만, **이 저장소는 겹치는 문서를
소유하고 있다.**

`docs/CODE_QUALITY_GUIDE.md` 는 이 프로젝트가 쓴 것이고, `guides/desktop/code-quality.md`
는 **그것을 증류한 것** 이다. 그리고 CTHarvester 는 아직 원본 쪽을 상대경로로 참조한다 —
`TODOs.md:9` 의 "Live status against `../Modan2/docs/CODE_QUALITY_GUIDE.md`", devlog 100·103.

공유본으로 기준을 옮기고 싶어지는데 **지금은 못 옮긴다**:

| | `docs/CODE_QUALITY_GUIDE.md` | `.guides/desktop/code-quality.md` |
|---|---|---|
| 절 수 | 14 | 7 |
| Appendix A (우선순위 채택 체크리스트) | 있음 | **없음** |
| Appendix B (도구 빠른 참조) | 있음 | 없음 |

같은 계보지만 **같은 문서가 아니다.** 공유본은 재구성·압축판이고, CTHarvester 의 상태표가
추적하는 체크리스트가 거기엔 없다. 옮기려면 체크리스트를 공유 가이드에 세우거나 그쪽 표를
다시 짜야 한다. **이번에는 어느 쪽도 손대지 않았다.** 정하기 전까지는 두 문서가 공존하고,
그 사실을 `CLAUDE.md` 에 적어 두었다 — 안 적으면 다음 사람이 둘 중 하나를 임의로 고른다.

## 다른 머신에서 거는 법

체크아웃은 비공개 문서 저장소의 **부분·희소 클론** 이다. `guides/` 만 받는다.

```
git clone --filter=blob:none --sparse <devdocs>
cd devdocs && git sparse-checkout set --no-cone '/guides/'
ln -s ../devdocs/guides .guides      # 형제 프로젝트 디렉터리에서
```

세 가지가 결정적이고 **셋 다 한 번씩 틀린 뒤에 알았다**:

- **`--no-cone` 이 필요하다.** cone 모드는 각 상위 단계의 파일을 **항상** 포함하므로 저장소
  루트 파일이 딸려 온다. 용량(수십 KB)이 아니라, `guides/` 만 있는 체크아웃 옆의 파이프라인
  스크립트가 **돌릴 수 있는 것처럼 보이는** 게 문제다.
- **패턴에 앞의 `/` 가 필요하다.** non-cone 은 gitignore 스타일이라 `guides` 는 **경로 어디에
  있든** 매칭된다 — 아카이브 안에 중첩된 무관한 `guides/` 가 실제로 딸려 왔다. `'/guides/'`
  가 루트에 앵커한다.
- **심볼릭 링크 대상은 상대경로로.** 형제 프로젝트가 놓이는 절대경로는 기계마다 다르다.
  WSL 에서 Windows 드라이브 위에 걸어도 동작하며, Windows 는 절대경로를 junction,
  상대경로를 디렉터리 심볼릭 링크로 본다.

**`--filter=blob:none` 은 "안 받는다" 가 아니라 "필요할 때 받는다" 다.** sparse-checkout 은
작업 트리만 제한하고 전송은 제한하지 않는다 — `git pull` 이 fast-forward 뒤 찍는 diffstat 만
해도 그 파일 blob 을 끌어온다.

## 바뀌지 않는 것

`MdModel`·`MdUtils`·빌드·의존성 전부 그대로다. 가이드는 여기서 작업하는 사람이 보는 참조
자료이지 프로그램의 입력이 아니다. 이 기록을 남기는 이유는 **`docs/` 에 가이드 사본이 없는
것이 누락이 아니라 결정으로 읽히게** 하기 위해서다.
