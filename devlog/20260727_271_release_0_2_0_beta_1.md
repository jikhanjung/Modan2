# 0.2.0-beta.1 릴리스

## 날짜
2026-07-27

## 배경

0.2 시리즈를 알파에서 베타로 올렸다. `0.2.0-alpha.2` 이후 53커밋이 쌓였고, 그 중
사용자에게 의미 있는 축은 두 가지다: **중첩정렬 완성**(devlog 250–254)과
**문서 전면 재정비**(devlog 260–269).

## 절차

`manage_version.py` 에 `stage beta` 명령이 있지만(0.2.0-alpha.2 → 0.2.0-beta.1)
`input()` 으로 확인을 받는 대화형이고 CHANGELOG를 빈 뼈대로 삽입한다. 같은 결과를
명시적으로 수행했다.

1. **`version.py`** — `0.2.0-alpha.2` → `0.2.0-beta.1`. 단일 출처이므로 이 한 줄이
   앱, `conf.py`(문서 제목), 설치 파일명을 모두 움직인다.
2. **`CHANGELOG.md`에 `## [0.2.0-beta.1]` 절 작성.** 이건 문서가 아니라 **릴리스
   본문 자체** 다 — `release.yml` 이 이 절을 awk로 추출해 GitHub 릴리스 본문으로
   쓴다. 그래서 워크플로와 **동일한 awk로 미리 추출을 검증** 했다(57줄, 다음 절로
   넘어가지 않고 정확히 끊김).
3. `docs/manual/changelog.rst` 미러링 + 한국어 18건 번역.
   (이 미러링 자체가 잘못된 구조라는 것이 이후 devlog 269에서 정리된다 — 릴리스
   시점에는 아직 두 파일을 손으로 유지하고 있었다.)
4. **태그 없이 먼저 커밋·푸시** 해 CI가 릴리스 대상 상태에서 green인지 확인.
5. 확인 후 `v0.2.0-beta.1` 태그 생성·푸시.

### 태그를 나중에 민 이유

로컬에서 pytest가 멈춰(원인은 devlog 270의 `-p no:xvfb` 함정) 커밋 전 전체 검증을
하지 못했다. 태그를 밀면 릴리스가 바로 나가므로, **버전 범프만 먼저 푸시해
CI 5개 워크플로가 green인 것을 확인한 뒤** 태그를 만들었다.

## 결과

`release.yml` 이 태그를 받아 **9개 잡 전부 성공**:

```
compute-build-number → test(ubuntu/windows/macos) + lint(ruff)
                     → build-linux/windows/macos → create-release
```

게시된 릴리스:

| 항목 | 값 |
|---|---|
| 태그 | `v0.2.0-beta.1` |
| prerelease | **true** (태그의 `-beta` 를 보고 자동 판정) |
| draft | false |
| 본문 | CHANGELOG 절 73줄 |

자산 4종, 빌드 번호 834가 3개 플랫폼에 일관되게 찍혔다:

- `Modan2-Windows-Installer-v0.2.0-beta.1-build834.zip` (127MB)
- `Modan2-macOS-Installer-v0.2.0-beta.1-build834.dmg` (133MB)
- `Modan2-Linux-v0.2.0-beta.1-build834.AppImage` (199MB)
- `SHA256SUMS.txt`

## 이번 세션 작업이 실제로 맞아떨어진 지점

- **설치 문서의 파일명이 방금 생성된 자산과 정확히 일치한다.** devlog 261에서
  실제 릴리스 자산을 확인해 고쳐 두지 않았다면, 문서는 존재하지 않는
  `Modan2-Setup.exe` 를 계속 안내하고 있었을 것이다.
- **문서 사이트도 함께 `0.2.0-beta.1` 로 갱신됐다.** devlog 265에서 `docs.yml` 의
  path 트리거에 `version.py` 를 추가해 둔 덕분이다. 그 수정이 없었다면 —
  `conf.py` 가 `version.py` 에서 버전을 가져오는데 트리거에는 없었으므로 —
  사이트에 `0.2.0-alpha.2` 가 그대로 남았을 것이다. 릴리스마다 재현될 문제였다.

## 남은 것

**macOS/Linux 빌드는 충분히 테스트되지 않은 상태다.** 그래서 설치 문서와 FAQ에
그 사실을 명시했고 릴리스도 prerelease로 나간다. 실제 설치가 확인되면 그 문구를
갱신할 수 있다.

그리고 이 베타에 포함된 **결측 랜드마크 대치**(devlog 227/254)는 분석 결과가
달라지는 변경인데 아직 실데이터로 검증되지 않았다 — 사용자만 할 수 있는 일이며,
남은 항목 중 가장 중요하다.
