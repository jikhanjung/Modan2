# 0.2.0-beta.3 릴리스 — P03를 담아서

## 날짜
2026-08-13

## 무엇이 담겼나

**P03의 네 단계 전부**(devlog 277·278·282·283)와 **Resistant Fit 철회**(devlog
281)다. beta.2가 "사용자가 소유한 것을 한 디렉터리에 모으는" 릴리스였다면 이번은
**그 디렉터리를 사용자가 고르고, 옮기고, 통째로 아카이브로 뽑는** 릴리스다.

릴리스 노트의 도입 문단을 그 관계로 썼다 — beta.2를 설치한 사람에게 이번 것이
무엇의 후속인지가 목록보다 먼저 와야 한다.

## 절차 — devlog 271·274와 같다

1. `version.py` 한 줄. 단일 출처이므로 앱·문서 제목·설치 파일명이 함께 움직인다.
2. `CHANGELOG.md` 의 `## [Unreleased]` 를 `## [0.2.0-beta.3] - 2026-08-12` 로
   바꾸고 도입 문단을 얹는다. 빈 `[Unreleased]` 자리표시자는 남기지 않는다(274와
   동일).
3. **`release.yml` 과 동일한 awk로 추출을 검증.** 106줄, beta.2 헤더로 넘어가지
   않고 정확히 끊겼다.
4. **태그 없이 먼저 커밋·푸시**, CI 5개 green 확인.
5. 태그 `v0.2.0-beta.3` 생성·푸시.

3번과 4번이 이 절차의 전부라고 해도 된다. CHANGELOG 절은 문서가 아니라 **릴리스
본문 그 자체**이고, 태그를 밀면 되돌릴 창이 없다.

## 태그 전에 확인한 것 — 두 베타 만에 두 번째 설정 이전

릴리스 노트가 "기존 환경설정은 첫 실행 때 자동으로 복사됩니다" 라고 **주장한다.**
노트가 주장하는 것은 태그 전에 확인해야 한다.

여기에는 한 겹이 더 있다. beta.2 사용자의 설정은 *아주 오래된* 경로가 아니라
**직전 베타가 만든** `~/PaleoBytes/Modan2/preferences.json` 에 있다. 즉 "옛
경로에서 옮긴다" 의 옛 경로가 둘이다.

```python
LEGACY_CONFIG_PATHS = (
    os.path.join(DEFAULT_DB_DIRECTORY, "preferences.json"),      # 0.2.0-beta.2
    os.path.join(USER_PROFILE_DIRECTORY, ".modan2", "config.json"),  # 그 이전
)
```

**최신 순으로 들어 있고 `migrate_legacy_config()` 가 첫 번째로 존재하는 것을
집는다.** 순서가 반대였다면 beta.2 사용자만, 그것도 조용히 설정이 초기화됐을
것이다 — 그 사용자에게는 창 배치와 언어가 그냥 사라진 것으로 보인다.

## 번역하지 않기로 한 것을 누락으로 오해할 뻔했다

릴리스 전 점검에서 `docs/manual/locale/ko/LC_MESSAGES/changelog.po` 가 **373건 중
370건 미번역**으로 나왔다. 릴리스 직전에 보기에 딱 나쁜 숫자다.

실제로는 커밋 `a999fa3` (`docs: Stop translating the changelog page`) 이
**changelog 페이지는 번역하지 않는다**고 결정하고 `.po` 를 git-ignore 했다.
`changelog.rst` 가 `CHANGELOG.md` 전체를 include 하는 순간 릴리스 히스토리 전부가
번역 단위가 되어 매 릴리스마다 미번역이 늘어나기 때문이다. 내 작업 트리의 파일은
그 결정 이전의 잔여물이었다.

**교훈은 파일이 아니라 결정을 봐야 한다는 것이다.** git-ignore 된 파일은 작업
트리에 남아 있어도 저장소의 결정을 더 이상 반영하지 않는다. 그리고 이 경우
잔여 파일이 가리키는 방향은 결정과 **정반대**였다 — "번역이 밀렸다" 로 읽힌다.

같은 커밋이 남긴 더 고약한 함정도 기록해 둔다: **Sphinx는 `.po` 가 아니라 컴파일된
`.mo` 를 읽는다.** 옛 `.mo` 가 남아 있으면 `.po` 를 지워도 한국어가 계속 렌더되어
"제외가 안 먹는다" 처럼 보인다.

## `gh run list --commit` 이 조용히 빈 목록을 준다

CI 감시를 `gh run list --commit 47f967c` 로 걸었는데 **아무것도 나오지 않았다.**
오류가 아니라 빈 결과였고, 그래서 감시 스크립트에서 **"아직 안 끝났다" 와 구별되지
않았다.** 5개가 전부 끝난 뒤에도 알림이 오지 않았고, 사용자가 먼저 알아챘다.

`--json headSha` 로 받아 직접 필터링하니 5개 전부 success로 나왔다.

**감시 스크립트에서 빈 결과를 미완료와 같게 취급하면 영원히 울리지 않는다.**
조회가 0건을 돌려주는 것과 조건이 아직 아닌 것은 다른 사건인데, 폴링 루프의 기본
구조는 둘을 합쳐 버린다. 판정에 쓰는 필드(`headSha`)를 직접 받아 거르는 편이
서버 측 필터 플래그를 믿는 것보다 안전하다.

## 남는 것

- **Windows 설치 관리자의 런타임 동작은 여전히 미검증이다.** devlog 274가 남긴
  항목 그대로 — 구버전 감지가 실제로 뜨는지, 깨끗한 머신에서 뜨지 *않는지*.
  빌드가 성공한다는 것은 Inno가 컴파일됐다는 뜻이지 프롬프트가 옳다는 뜻이 아니다.
- **라이브러리 이전과 백업은 실제 사용자 데이터에서 아직 돌아 보지 않았다.**
  테스트는 충분하지만(2단계 이전 + 4단계 백업 합쳐 수십 건, 불변식 위주), 베타의
  목적이 정확히 이 간극을 메우는 것이다.
- P02(아웃라인·EFA)는 계획서만 있고 코드는 없다. 다음 큰 덩어리는 그쪽이다.
  **버전은 `0.3.0` 으로 정했다**(2026-08-13) — 근거는 P02 계획서의 "버전" 절에
  적었다. 요지는 1.0이 기능이 아니라 **저장 포맷을 깨지 않겠다는 약속** 이고, 그
  포맷이 아직 릴리스마다 움직이는 중이라는 것이다.
