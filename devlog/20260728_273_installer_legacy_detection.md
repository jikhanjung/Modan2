# 설치 관리자의 구버전 감지

## 날짜
2026-07-28

## 배경

devlog 272에서 `PrivilegesRequired=lowest` 와 GUID `AppId` 를 도입하면서 **설치
관리자가 기존 설치를 인식하지 못하게** 됐다. 릴리스 노트에 "구버전을 먼저
제거하세요"라고 쓰는 것으로 넘어가려 했는데, 확인해 보니 그 안내만으로는
부족했다.

## 왜 "그냥 두 개 깔려 있어도 된다"가 아닌가

두 설치는 `{app}` 폴더가 분리돼 있고(Roaming vs Local), PyInstaller onedir는
자기완결형이라 실행에는 서로 간섭하지 않는다. DB도 `MdModel.py:194` 가 홈
디렉터리에서 경로를 계산하므로 설치 위치와 무관하게 공유된다. 여기까지는
문제가 없다.

문제는 **설치 관리자가 `{app}` 밖에도 쓴다**는 점이다. 이 두 항목은 `{app}` 에
의존하지 않는 리터럴 경로라 **두 설치가 같은 자리를 쓴다**:

| 무엇 | 경로 | 템플릿 |
|---|---|---|
| 시작 메뉴 바로가기 | `{userprograms}\PaleoBytes\Modan2` | `:52` |
| 예제 데이터셋 | `{%userprofile}\PaleoBytes\Modan2\ExampleDataset` | `:35` |

Inno의 언인스톨러는 자기가 설치한 파일 목록을 로그에 남기고 제거 시 그것을
지운다. 새 버전을 먼저 설치하면 이 두 경로를 덮어쓰지만, **구버전 언인스톨
로그에는 여전히 같은 경로가 남아 있다.**

따라서 `새 버전 설치 → 구버전 제거` 순서로 하면:

- 새 버전을 가리키던 시작 메뉴 바로가기가 사라진다
- `ExampleDataset` 이 사용자 데이터 디렉터리에서 삭제된다

실행 파일 자체는 멀쩡하지만 사용자에게는 "설치했는데 시작 메뉴에 없다"가 된다.
**순서가 중요한데, 순서를 안내문에만 맡기는 것은 약하다.**

## 구현

`[Code]` 에서 구버전 언인스톨 키를 찾아 감지하고, 지금 제거할지 물어본다.

### 무엇을 찾는가

0.2.0-beta.1 이하는 `AppId` 가 없어 `AppName` 이 대신 쓰였으므로 키 이름이
`Modan2_is1` 이고, admin 모드로 설치됐으므로 HKLM에 있다.

```
Software\Microsoft\Windows\CurrentVersion\Uninstall\Modan2_is1
```

새 설치는 GUID AppId를 쓰므로 키 이름이 달라 **자기 자신을 감지하지 않는다.**

레지스트리 뷰는 네 곳을 다 본다(`HKLM32` / `HKCU32`, 그리고 64비트 Windows에서만
`HKLM64` / `HKCU64`). 32비트 모드 Inno 설치는 32비트 뷰에 들어가지만 그것을
전제하지 않았다. 32비트 Windows에서 64비트 뷰에 접근하면 예외가 나므로
`IsWin64` 로 가드한다.

### 제거를 기다리는 방법

Inno 언인스톨러는 **자신을 임시 폴더로 복사해 재실행**하기 때문에, 원래
프로세스는 작업이 끝나기 전에 종료된다. `Exec(..., ewWaitUntilTerminated, ...)`
가 돌아왔다고 제거가 끝난 것이 아니다.

그래서 프로세스가 아니라 **레지스트리 키가 사라지는 것을 기다린다.** 최대
120초까지 0.5초 간격으로 폴링하고, 시간이 지나면 매달리지 않고 포기하며 수동
제거를 안내한다.

### 선택지

`MB_YESNOCANCEL` 세 갈래다.

- **예** — 구버전 언인스톨러를 `/SILENT /NORESTART /SUPPRESSMSGBOXES` 로 실행하고
  위 방식으로 대기. 실패하면 안내 후 설치를 중단한다.
- **아니오** — 그대로 나란히 설치한다. 경고문에서 무슨 일이 생기는지 이미
  설명했으므로 사용자의 선택을 존중한다.
- **취소** — 설치를 중단한다.

**신규 사용자에게는 아무 일도 일어나지 않는다.** 키가 없으면 `InitializeSetup`
은 프롬프트 없이 바로 통과한다. 이 점이 가장 중요한 제약이었다 — 감지 로직의
버그가 깨끗한 설치를 막으면 안 된다.

## 검증

**Inno는 Windows에서만 컴파일된다. 이 코드는 실행된 적이 없다.** 오프라인에서
확인 가능한 것만 확인했다:

- `begin`/`end` 균형 (11/11). 문자열 리터럴과 `//` 주석을 제거한 뒤 셌다.
- **선언 순서** — Pascal Script는 단일 패스라 호출 전에 선언돼야 한다.
  `FindLegacyUninstaller` → `LegacyStillRegistered` → `WaitForLegacyRemoval` →
  `RemoveLegacyInstall` → `InitializeSetup` 순이고, 모든 호출이 앞선 선언을
  가리키는 것을 스크립트로 확인했다.
- **`build.py` 치환과의 충돌 없음** — `[Code]` 안에 `{{` 가 없다. 치환 후 남는
  `{{` 는 `AppId` 이스케이프 한 줄뿐임을 드라이런으로 확인했다.
- 줄바꿈 CRLF 169줄, 혼합 없음.
- `tests/test_version_consistency.py` 통과.

주석 안의 `{userprograms}` 같은 문자열은 `//` 줄 주석 안에 있어 Pascal의 `{ }`
블록 주석으로 해석되지 않는다.

## 남은 것

**Windows에서 네 경우를 실제로 시험해야 한다** (TODOs에 기록):

1. 구버전 있음 + "예" → 제거되고 설치 진행
2. 구버전 있음 + "아니오" → 나란히 설치
3. 구버전 있음 + "취소" → 설치 중단
4. **구버전 없음 → 프롬프트가 아예 뜨지 않아야 한다**

4번이 회귀 위험이 가장 크다. 1~3번이 다 잘 돼도 4번이 깨지면 모든 신규 사용자가
영향을 받는다.
