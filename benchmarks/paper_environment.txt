Environment and commands behind paper_runtime_cranial206.json,
paper_accuracy_cranial222.json, paper_accuracy_dense14.json (the runtime and
accuracy tables of the Modan2 paper), paper_worked_examples_cranial206.json
(the figures of its worked example on the cranial dataset), and
paper_r_comparison_cranial206.json (the same analyses compared with an
independent R implementation), and paper_refinement_sensitivity.json (the
accuracy assessment repeated with the cap on refinement rounds raised from 5
to 10 and 20).

Code: Modan2 v0.2.0 (tag v0.2.0, commit 5173275, clean), run from a
git worktree at the tag through --repo. The scripts themselves are run from
this checkout; they postdate the tag, and only load the application code from
the worktree.

The runtime table uses the 206 specimens of known diet (dataset cranial206:
the 16 thylacines, coded FeedCat1 = Unknow, are excluded), so that CVA and
MANOVA compare the same 10 dietary groups as the worked example. It replaces
paper_runtime_cranial222.json, which kept the thylacines as an 11th group.
The accuracy table uses all 222 specimens, since it involves no grouping.

Machine: Intel Core i7-6700 (3.40 GHz, 4 cores / 8 threads), 16 GB RAM,
Windows host running Linux under WSL 2
(kernel 5.15.167.4-microsoft-standard-WSL2, glibc 2.39).

Commands (run one after another, 2026-10-08):
  python scripts/benchmark_paper_tables.py --repo <worktree> --dataset cranial206 --runs 9 --markdown \
      --out benchmarks/paper_runtime_cranial206.json
  python scripts/benchmark_paper_tables.py --repo <worktree> --accuracy --markdown \
      --out benchmarks/paper_accuracy_cranial222.json
  python scripts/benchmark_paper_tables.py --repo <worktree> --accuracy --dataset dense14 --markdown \
      --out benchmarks/paper_accuracy_dense14.json
  python scripts/paper_worked_examples.py --repo <worktree>
  python scripts/paper_r_comparison.py --repo <worktree> \
      --rscript ~/micromamba/envs/modan2-r/bin/Rscript
  python scripts/paper_refinement_sensitivity.py --repo <worktree>

The R side runs in the micromamba environment of r-environment.yml (R 4.5.3,
geomorph 4.1.1, RRPP 2.2.0, MASS 7.3-66, OpenBLAS 0.3.34); that file says how
to rebuild it. Repeated runs of the comparison differ around 1e-14, because
the ARPACK solver of Modan2's CVA starts from a random vector.

Removal patterns come from the script's default seed, 20260813 (pattern p at
missing fraction f uses seed 20260813 + 101 p + int(1000 f) in accuracy
mode, and 20260813 + int(100 f) in the runtime table). The JSON files do not
record the seed themselves. The accuracy results are identical, to the last
digit, to the earlier runs on 0.2.0-beta.3, which used the same seed, and to
the first runs on v0.2.0, made before the accuracy mode recorded how the
imputation loop ended ("refinement" in each condition).
