# CVA 계획 — 판별 전에 차원을 줄이고, 정직한 정확도를 보고한다

## 날짜
2026-08-13

## 개정 (2026-08-13) — 검토 반영

계획을 검토하면서 진단을 **그룹 구조가 전혀 없는 난수**로 재현했다. 222 × 216,
11군, 최소군 2로 만든 순수 잡음에서:

```
resubstitution accuracy : 100.0%   (chance = 9.1%)
```

**신호가 0인 데이터에서도 100%가 나온다.** 원 진단이 옳다는 것이 이걸로 확정됐다.

같은 데이터로 설계 선택지를 비교한 결과 **한 가지를 바꿨다**:

| 방식 | 정확도 (참값 9.1%) |
|---|---|
| 재대입 | 100.0% |
| CV, PCA를 루프 **밖**에서 적합 (2겹) | 12.6% |
| CV, PCA를 루프 **안**에서 적합 (2겹) | 10.4% |
| LOOCV, PCA를 루프 안에서 | 9.5% |

초안대로 "축소 후 교차검증" 을 두 단계로 구현하면 **전체 데이터로 적합한 PCA
점수를 교차검증**하게 되어 테스트 폴드가 자기 주성분 계산에 참여한다. 신호가 없는
데이터에서 참값보다 3.5%p 높게 나오는 것이 그 누수의 크기다. 100%보다야 훨씬
낫지만, 이 수정의 동기가 "심사자가 과적합을 지적할 값" 이었으므로 **같은 심사자가
지적할 수 있는 종류를 남기는 것**은 목적에 어긋난다.

바뀐 것과 그대로인 것:

- **축소는 교차검증 파이프라인의 일부다. 그 전 단계가 아니다.** (2·3단계 통합)
- **교차검증은 LOOCV를 기본으로 한다.** 결정적이고, 최소군 크기에 따른 특수
  케이스가 사라진다 (아래 3단계).
- **기준선을 함께 보고한다.** 불균형 11군에서 정확도 25%가 좋은지 나쁜지는 그
  자체로 판단할 수 없다.
- **`accuracy` 키를 재정의하지 않고 갈라놓는다** (아래 3단계).
- 1단계(축소를 `do_cva_analysis` 안에서)와 축소 규칙의 세 항 상한은 그대로다.

`k` 자체를 전체 데이터의 95% 기준으로 고르는 것도 엄밀히는 같은 종류의 누수지만,
그룹 라벨을 쓰지 않는 비지도 선택이라 관례상 허용된다. **문서에 그렇게 적는 것으로
처리하고 숨기지 않는다.**

## 배경 — 어떻게 발견했나

dissertation Chapter 2(Modan2 논문)의 worked example에 실제 통계 수치를 넣으려고
Rovinsky et al. (2021) 두개골 데이터셋(222 표본 × 72 랜드마크, 3D)으로 CVA를
돌렸다. 결과:

```
FeedCat1 (식이 범주, 11군):  accuracy = 100.0
PreyRatio (먹이 크기, 7군):  accuracy = 100.0
```

두 그룹 변수 모두 분류 정확도가 정확히 100%다. 그룹 수가 11개이고 가장 작은 군은
표본이 2개(`InsHer`)뿐인데도 그렇다. **이 값은 논문에 넣지 않았다** — 심사자가
곧바로 과적합을 지적할 값이기 때문이다. 대신 CVA 고유값 비율만 인용했다.

## 원인

`MdStatistics.do_cva_analysis` 가 Procrustes 정렬 좌표를 **평탄화한 그대로**
LDA에 넣는다.

```python
data_matrix = np.array(flattened_data)      # 222 x 216
lda = LinearDiscriminantAnalysis()
cv_scores = lda.fit_transform(data_matrix, group_array)
predictions = lda.predict(data_matrix)      # 훈련에 쓴 바로 그 데이터
accuracy = accuracy_score(group_array, predictions) * 100
```

변수가 216개(랜드마크 72 × 3차원), 표본이 222개다. 판별분석에서 군내 산포행렬의
자유도는 대략 `n − g` = 222 − 11 = 211 인데 변수가 216개이므로 **군내 산포행렬이
특이하거나 특이에 가깝다.** 이 조건에서 선형판별은 어떤 그룹 분할이든 완벽하게
분리한다. 그룹이 실제로 다른지와 무관하다.

여기에 두 번째 문제가 겹친다. 정확도를 **훈련에 사용한 바로 그 데이터로**
측정한다(재대입, resubstitution). 과적합된 모형의 재대입 정확도는 정의상 100%에
가깝고, 아무 정보도 담고 있지 않다.

사용자에게는 "완벽하게 분류된다"로 읽힌다. 즉 이 숫자는 비어 있는 정도가 아니라
**적극적으로 오해를 부른다.**

## 그리고 일관성 문제이기도 하다

같은 분석 실행 안에서 MANOVA는 이미 차원을 줄인다. `ModanController._run_manova`:

```python
# 누적 분산 95% 지점까지의 성분 수, 단 20개 상한
for i, eigenvalue in enumerate(eigenvalues):
    cumulative_variance += eigenvalue
    if cumulative_variance / total_variance >= 0.95:
        effective_components = i + 1
        break
...
manova_data = [score[:effective_components] for score in pca_scores]
```

이 데이터셋에서 13개 성분이 선택된다. 즉 **하나의 PCA 분석 실행에서 MANOVA는
13차원을, CVA는 216차원을 본다.** 두 검정이 같은 데이터를 보고 있다고 믿을 근거가
없고, 결과를 나란히 해석할 수도 없다.

`MdStatistics.py` 는 이미 MANOVA 쪽에 축소 개념을 갖고 있다 —
`MANOVA_MAX_VARIABLES = 20` 과, 결과에 `n_variables_total` /
`n_variables_used` / `truncated` 를 실어 보내는 관례. CVA에는 그에 해당하는 것이
없다.

## 계획

### 1단계 — 축소를 `do_cva_analysis` 안에서 한다

MANOVA처럼 컨트롤러에서 줄이지 **않는다.** `do_cva_analysis` 는 테스트
(`test_mdstatistics.py`, `test_multi_analysis_workflow.py`)와 컨트롤러 양쪽에서
직접 불린다. 컨트롤러에만 고치면 함수를 직접 부르는 경로는 그대로 망가진 채
남는다. 축소는 함수 안에 두고, 시그니처는 그대로 유지한다.

### 2단계 — 축소 규칙, 그리고 축소는 파이프라인의 일부다

공용 헬퍼를 `MdStatistics` 에 두어 MANOVA와 CVA가 같은 규칙을 쓰게 한다.

```
k = min( 누적분산 95% 에 필요한 성분 수,
         MAX_VARIABLES (20),
         n_samples − n_groups − 1 )
k = max(k, 1)
```

세 번째 항이 이번 문제의 핵심이다. `n − g − 1` 은 군내 산포행렬을 비특이로 만드는
데 필요한 여유이고, 이것을 넘지 않는 한 판별은 자동으로 완벽해지지 않는다.
95% 기준만으로는 부족하다 — 표본이 적고 랜드마크가 많은 데이터셋(예: 동봉된
14 × 381)에서는 95%에 도달하는 성분 수가 이미 표본 수를 넘길 수 있다.

**변수 수가 이미 충분히 적으면 축소하지 않는다.** `n_features <= n_samples −
n_groups` 이면 원좌표를 그대로 쓴다. 잘 조건화된 소규모 데이터셋의 현행 동작을
바꾸지 않기 위해서다.

이 데이터셋에서는 `min(13, 20, 210) = 13` 이 되어 **MANOVA와 정확히 같은 13차원**을
본다. 목표했던 일관성이 여기서 확보된다.

**축소는 별도 단계가 아니라 추정기의 일부로 구현한다:**

```python
estimator = make_pipeline(PCA(n_components=k), LinearDiscriminantAnalysis())
```

이렇게 두면 3단계의 교차검증이 **폴드마다 PCA를 다시 적합**한다. 축소를 먼저
수행하고 그 결과를 교차검증하면 테스트 폴드가 자기 주성분 계산에 참여한다(개정
노트의 12.6% 대 10.4%). 축소가 필요 없는 경우(`n_features <= n_samples −
n_groups`)에는 파이프라인 없이 LDA 하나를 그대로 쓴다.

보고용 canonical variables는 같은 추정기를 전체 데이터에 적합해 얻는다. 교차검증은
정확도를 재기 위한 것이고, 화면에 그리는 좌표는 전체 데이터로 적합한 모형의
것이어야 한다 — 이 둘은 다른 목적이며 섞으면 안 된다.

### 3단계 — 정확도를 교차검증으로 보고한다

**LOOCV(Leave-One-Out)를 기본으로 한다.** 초안의 층화 K겹 대신인 이유가 셋이다.

1. **특수 케이스가 사라진다.** 층화 K겹은 겹 수가 최소군 크기에 묶여
   (`min(5, 최소군)`) 이 데이터셋에서 2겹이 되고, 최소군이 1이면 아예 불가능해
   "교차검증 불가" 분기와 그 테스트가 필요해진다. LOOCV에는 최소 군 크기 조건이
   없다. 1개짜리 군의 표본은 그냥 틀리게 분류될 뿐이고, **그것이 정직한 답이다.**
2. **결정적이다.** 폴드 배정에 무작위성이 없다. 학위논문에 인용할 수치라면 재실행이
   같은 값을 내야 한다.
3. **관례와 맞는다.** R의 `MASS::lda(CV=TRUE)` 가 LOOCV이고, 형태측정학 독자가
   "교차검증 분류 정확도" 로 기대하는 값이 그것이다.

개정 노트의 표에서 참값(9.1%)에 가장 가까운 것도 LOOCV였다.

**표본이 많으면 층화 K겹으로 물러선다.** LOOCV는 표본 수만큼 적합하므로 큰
데이터셋에서 비용이 문제가 된다. 측정 결과:

| 크기 | LOOCV |
|---|---|
| 222 × 216 (이 데이터셋) | 4.3초 |
| 500 × 1000 | 264초 |
| 1000 × 2000 | 1027초 |

**표본 4배에 시간 240배다.** 비용이 변수 수에도 강하게 좌우되므로 **표본 수만으로
임계값을 잡으면 안 된다** — 넓은 데이터셋이 조용히 수 분을 먹는다. 예산을
`n_samples × n_features` 로 잡고(`CVA_LOOCV_MAX_WORK = 200_000`), 물러설 때도
`shuffle=False` 로 결정성을 유지한다. 어느 쪽을 썼는지는 `accuracy_method` 가
밝힌다.

**반환 키 — `accuracy` 를 재정의하지 않고 없앤다.**

초안은 `accuracy` 를 교차검증 값으로 바꾸고 옛 값을 `resubstitution_accuracy` 로
옮기려 했다. 대신 **`accuracy` 라는 이름 자체를 없앤다:**

| 키 | 내용 |
|---|---|
| `cross_validated_accuracy` | LOOCV(또는 K겹) 정확도 |
| `resubstitution_accuracy` | 기존 값. 참고용으로 남긴다 |
| `accuracy_method` | `"leave-one-out"` / `"stratified 5-fold"` 등 |
| `chance_accuracy` | 최빈군 비율. 기준선 없이는 정확도를 해석할 수 없다 |
| `n_variables_total` / `n_variables_used` / `reduced` | MANOVA의 보고 관례를 그대로 따른다 |

이유는 **조용히 다른 숫자를 받는 것보다 시끄럽게 실패하는 편이 낫기 때문**이다.
같은 이름이 릴리스에 따라 다른 정의를 갖게 되면 옛 코드는 아무 일 없다는 듯
동작하면서 다른 값을 쓴다. 이름을 없애면 `KeyError` 가 난다.

**지금이 그렇게 하기에 가장 싼 시점이다.** 소비처가 `ModanController._run_cva` 와
`ModanWidgets._get_cva_summary` 둘뿐이고(4단계의 정정 참조), **`_serialize_cva_result`
는 이 값을 DB에 저장하지 않는다.** 즉 옛 정의의 정확도를 들고 있는 저장 데이터가
없으므로 이름을 바꾸는 비용이 사실상 0이고, 다음 소비처가 생긴 뒤에는 0이 아니다.

`ModanController._run_cva` 의 `cva_result.get("accuracy", 0.0)` 도 함께 고친다.
**`.get(..., 0.0)` 을 남겨 두면 키가 사라져도 조용히 0.0이 흐른다** — 없애려는 실패
방식 그 자체다.

**교차검증 정확도는 100%보다 한참 낮게 나올 것이고, 그것이 요점이다.** 값이
떨어졌다고 회귀로 읽지 않도록 릴리스 노트에 적어야 한다.

### 4단계 — UI

**정정 (구현 중 발견).** 초안은 "`accuracy` 를 화면에 표시하는 코드는 없다" 고 했고
근거로 `dialogs/`·`components/` 를 들었다. **그 두 곳에 없는 것은 맞지만, 저장소
루트의 `ModanWidgets.py:868` 에 있다:**

```python
def _get_cva_summary(self) -> str:
    accuracy = results.get("accuracy", 0.0)
    return f"...<b>Classification accuracy:</b> {accuracy:.1f}%..."
```

**검색 범위가 좁았다.** 살아 있는 UI가 `dialogs/`·`components/` 에 있다는 것은
맞지만, 그것이 저장소 전체를 뒤지지 않아도 된다는 뜻은 아니었다.

그리고 이 코드가 하는 일이 정확히 초안이 경고한 것이다 — **방법을 밝히지 않은
분류 정확도**. devlog P04의 100%가 사용자에게 도달한 형태가 이 문장이다. 게다가
`.get(..., 0.0)` 이라 키가 사라지면 "정확도 0.0%" 를 조용히 표시한다.

따라서 UI 변경이 이번 범위에 **들어온다**: 교차검증 값을 쓰고, `accuracy_method`
와 `chance_accuracy` 를 값 옆에 함께 보인다.

다만 `ModanWidgets.py` 는 **애플리케이션이 import 하지 않는다** —
`MdConstants.py` 의 로깅 설정과 자기 테스트 파일만 이 이름을 언급한다. 즉 사실상
죽은 모듈로 보인다. 그것은 별개의 정리 문제이므로 여기서는 판단하지 않고, 살아
있다는 전제로 고쳐 둔다. **죽었다고 단정하고 방치하면, 살아 있었을 때 틀린 숫자를
보이는 쪽으로 실패한다.**

## 기존 테스트에 미치는 영향

`tests/test_mdstatistics.py::TestCVAAnalysis` 세 건은 모두 축소 경로를 타게 된다:

| 테스트 | n / 군 / 변수 | `n−g−1` | 축소 후 | 단언 통과 여부 |
|---|---|---|---|---|
| `basic` | 6 / 2 / 6 | 3 | ≤3 | `len(canonical_variables) == 6` (표본 수) — 통과 |
| `three_groups` | 6 / 3 / 4 | 2 | ≤2 | `n_components == 3` (3으로 패딩) — 통과 |
| `padding` | 4 / 2 / 4 | 1 | 1 | `n_components == 3` (패딩) — 통과 |

세 건 모두 표본 수와 패딩된 성분 수만 단언하므로 그대로 통과할 것으로 보이지만,
**실행해서 확인해야 한다.** `test_controller.py:339` 는 `do_cva_analysis` 를
mock 하므로 무관하다.

`test_do_cva_analysis_basic` 은 `assert "accuracy" in result` 를 단언하므로
**고쳐야 한다.** 그것이 키를 없애는 목적이다 — 계약이 바뀌면 계약을 적어 둔 곳이
실패해야 한다.

축소 규칙 자체를 직접 겨냥한 테스트를 새로 추가한다:

1. **그룹 구조가 없는 난수에서 재대입은 100%인데 교차검증은 우연 수준이다.**
   이 문제의 회귀 테스트이고, 개정 노트의 재현을 그대로 테스트로 굳힌 것이다.
   실제 데이터를 쓰면 "낮게 나온다" 밖에 단언할 수 없지만, 신호가 0인 데이터에서는
   **정답을 알고 있으므로** 우연 수준 근처라는 강한 단언이 가능하다.
2. 같은 데이터에서 CVA가 쓴 변수 수와 MANOVA가 쓴 변수 수가 일치한다.
3. 변수 수가 이미 적으면 축소가 일어나지 않는다(`reduced == False`).
4. 1개짜리 군이 있어도 예외가 나지 않고 정확도가 보고된다 — 초안의 "교차검증 불가"
   분기가 LOOCV에서는 필요 없다는 것의 확인.
5. 같은 입력을 두 번 분석하면 정확도가 **정확히 같다**(결정성).

## 위험

1. **저장된 분석 결과와의 불연속.** 새 CVA는 이전 버전과 다른 canonical variable
   값을 낸다. 기존 DB의 결과는 그대로 남으므로 같은 데이터셋을 다시 분석하면
   숫자가 달라진다. 릴리스 노트에 명시해야 하고, 논문에 인용한 CVA 고유값 비율
   (CV1 74.0%, CV2 16.2%)도 **수정 후 다시 뽑아 갱신해야 한다.**

   범위를 좁혀 두자면, **불연속은 canonical variables 에만 해당한다.** 그것은
   `cva_analysis_result_json` 으로 저장되지만 정확도는 저장되지 않으므로(3단계
   참조), 저장된 데이터가 옛 정의의 정확도를 들고 있는 경우는 없다.
2. **축소가 군 간 차이를 실제로 버릴 수 있다.** 95% 분산 기준은 분산이 큰 축을
   남기지 군을 잘 가르는 축을 남기지 않는다. 이론적으로는 판별 신호가 하위 성분에
   있을 수 있다. 다만 MANOVA가 이미 같은 기준을 쓰고 있으므로 새로 도입되는
   위험이 아니라 **이미 존재하는 선택을 CVA로 확장하는 것**이다. 두 검정이
   불일치하는 현 상태보다 낫다.
3. **작은 군에서 교차검증이 불안정하다.** LOOCV로 바꾸면서 초안의 2겹 문제는
   없어졌지만, 표본이 2개인 군의 정확도가 0% 또는 50% 또는 100% 셋 중 하나라는
   사실은 남는다. `chance_accuracy` 를 함께 보고하는 것이 이에 대한 부분적인
   답이고, 나머지는 사용자가 군 크기를 보고 판단할 몫이다.

4. **축소된 차원이 폴드 안에서는 여유가 더 적다.** `n − g − 1` 은 전체 표본으로
   계산하는데 폴드의 훈련 집합은 그보다 작다. 홀드아웃 예측이므로 가짜 100%가
   되지는 않고(그것이 교차검증의 요점이다) 추정이 시끄러워질 뿐이다. LOOCV는
   `n_train = n − 1` 이라 이 간극이 사실상 없다 — LOOCV를 택하는 부수적 이유 하나.

## 같은 함수에서 눈에 띈 것 (이번 변경이 만든 것은 아님)

`group_centroids` 는 **0으로 패딩된 열까지 포함한 `cv_scores` 로 계산된다**
(`MdStatistics.py:459`). 군이 2개일 때 실제 판별축은 1개인데 중심은 3차원으로
나오고 뒤 두 성분은 항상 0이다. 틀린 값은 아니지만 의미 없는 자리가 섞여 있다.
같은 함수를 손대는 김에 확인은 하되, 고치면 UI 호환성(3차원 가정)에 걸리므로
**이번 범위에서는 건드리지 않고 기록만 남긴다.**

## 후속으로 미뤄둘 것

MANOVA의 성분 선택 로직이 `ModanController._run_manova` 안에 있다. 공용 헬퍼를
`MdStatistics` 에 만들고 나면 MANOVA도 그것을 쓰도록 옮기는 것이 맞지만, 컨트롤러
경로를 건드리는 변경이라 이번 계획에서 분리한다. 1차에서는 헬퍼를 만들고 CVA만
연결한다.

## 구현 결과 (2026-08-13)

논문 데이터셋과 **같은 형태이면서 그룹 구조가 전혀 없는** 난수(222 표본 × 72
랜드마크 × 3D = 216변수, 11군, 최소군 2)로 확인:

```
variables  216 -> 20   (reduced=True)
resubstitution accuracy    : 33.8%
cross-validated accuracy   : 10.4%   [leave-one-out]
chance (largest group)     : 9.9%
elapsed                    : 7.1s
```

**신호가 0인 데이터에서 100%였던 것이 우연 수준(10.4% 대 9.9%)으로 내려왔다.**
축소만으로도 재대입이 100% → 33.8%로 떨어지고, 남은 33.8%가 과적합이라는 것을
교차검증이 드러낸다. **두 수치를 나란히 두는 것이 요점이다** — 한쪽만으로는 이
데이터에 아무것도 없다는 것을 알 수 없다.

여기서 축소를 결정한 것은 95% 기준이 아니라 `MANOVA_MAX_VARIABLES` 상한(20)이다.
난수는 모든 성분의 분산이 같아 95%에 도달하는 데 ~205개가 필요하기 때문이다.
실제 데이터에서는 95% 기준이 먼저 걸려 계획대로 13이 될 것이다. **세 항 중
무엇이 걸리는지가 데이터에 따라 다르다는 것 자체가 세 항을 모두 두는 이유다.**

변경한 파일:

- `MdStatistics.py` — `effective_component_count` (공용), `do_cva_analysis` 재작성,
  `_cross_validated_accuracy`, `CVA_LOOCV_MAX_WORK`
- `ModanController.py` — 새 키 전달, `.get(..., 0.0)` 제거
- `ModanWidgets.py` — 방법과 기준선을 값과 함께 표시
- 테스트 — `test_mdstatistics.py` 에 `TestCVADimensionality` 9건, 기존 CVA 계약
  테스트 2건 수정, `test_controller.py` 의 mock 갱신

## 아직 안 한 것

- **MANOVA를 공용 헬퍼로 옮기기.** 계획대로 분리해 뒀다. `_run_manova` 는 여전히
  자기 안에서 95%/20 규칙을 계산하며, `n − g − 1` 항이 없다. 지금은 두 분석이
  **같은 규칙을 쓰되 코드가 두 벌**인 상태다.
- **논문 수치 갱신.** CV1 74.0% / CV2 16.2% 는 옛 코드의 값이다.
- **실제 데이터셋으로 확인.** 위 검증은 난수로 한 것이다. 난수는 정답을 알기
  때문에 회귀 테스트로는 더 강하지만, 실제 데이터에서 얼마가 나오는지는 별개다.
